# 네 폼 자동 시나리오

각 사례는 시작 폼, 사용자 문장, 독립적인 편집 동작으로 정의한다. `set`은 지정한 값으로 바꾸고 `clear`는 비운다. `replace`는 날짜 목록에서 기존 원소 하나를 교체한다. `manual`은 다음 메시지를 보내기 전에 사용자가 직접 고친 값이다. `previous`는 미확정 제안을 잇고, `reset`·`hold`는 해당 필드를 현재 폼 값으로 둔다. 나머지 필드는 기존 기대 후보를 이어간다. 같은 값 재확인은 변경 성공에 포함하지 않는다.

러너는 Node의 실제 업체 도우미 세션을 열어 각 문장을 보낸다. 세션이 만든 규칙 후보와 직전 대화 문맥을 Python 해석 서비스로 전달한다. 다음 턴에는 직전 **실제 응답**에서 만들어진 후보가 들어간다. 정답 동작은 채점기에만 전달한다. 중간 턴에서는 미리보기까지 확인하고 마지막 턴에서 시뮬레이션한 사용자가 유효 후보를 모두 선택해 적용한다. 충돌 대안은 보류한다. 적용 점수는 폼 콜백에 전달된 변경값을 측정한다. 실제 견적 저장·발송은 평가 범위 밖이다.

| 기준 | 의미 |
|---|---|
| wrong | 시작값과 달라졌으며 목표값에도 맞지 않은 필드 |
| missed | 시작값에서 바뀌어야 했지만 목표값에 도달하지 못한 필드 |
| correct | 필요한 변경을 목표값과 일치하게 수행한 필드 |
| exact | 모든 필드의 최종값이 기대 상태와 일치한 턴 |

100만 원을 120만 원으로 바꿔야 하는데 130만 원이 나오면 wrong과 missed에 각각 1을 기록한다. 단순 미추출은 missed에만 잡힌다. 결과 JSON에 각 필드명·현재값·기대값·후보·적용값이 남는다. 보류와 거부는 최종 폼 보존 관점으로 채점한다. 이 테스트는 사람이 정답을 검수하지 않아도 같은 편집 결과를 반복해서 검사하는 기능 평가다.

저장소 루트에서 백엔드 의존성과 Node 24가 준비된 환경으로 실행한다.

```sh
uv run --project backend python -m evaluation.vendor_assist.scenarios.run --json scenario-rule.json
uv run --project backend python -m evaluation.vendor_assist.scenarios.run --live --form quote --json scenario-quote-live.json
uv run --project backend python -m pytest evaluation/tests/test_vendor_assist_scenarios.py -q
```

기본 실행은 무료 규칙 경로다. `--live`는 설정한 업체 모델로 실제 API를 호출한다. 모델 호출 실패 후 규칙으로 돌아온 턴은 fallback_turns에 별도로 표시하고 그대로 채점한다. CI는 무료 규칙 경로에서 이전에 관측한 잘못된 변경과 누락을 필드 단위로 대조한다. 새 실패는 CI를 실패시킨다. 기존 실패를 허용 목록에 자동으로 추가하지 않는다. 개선이 확인된 실패는 기준 파일에서도 제거한다.
